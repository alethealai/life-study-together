# 維護說明

## 閱讀與換書

共同目標展示與目標輸入已從介面移除；共讀書目由管理者右上角選單的「共讀書目設定」調整。同伴區只顯示目前選中的成員進度。既有 target 欄位暫留於資料模型與請求中以相容已部署的後端，不再用於畫面比較或進度提醒，無須遷移或刪除既有資料。

個人進度卡可直接完成下一章／篇／單元；「更新進度」使用讀完至選單，儲存前顯示新增的連續範圍。「更新多項進度／補登」保留多書目與日期輸入。兩種入口都沿用同一個 callable、版本檢查與請求去重，沒有逐篇 checkbox 文件，也不支援跳篇勾選。開啟閱讀連結不自動記錄完成。

閱讀目錄依目前位置推導已讀狀態，不查詢歷史明細。生命讀經篇題在開啟目錄時按需載入 `lib/life-study-titles.json`；以 `python3 scripts/import-life-study-titles.py` 從 LSM 官方索引更新，並核對 66 個書卷入口的篇數與既有閱讀連結一致。長篇題保留頭尾，點選後顯示完整篇題。李常受文集重用既有靜態章篇目錄。

`recordReading`、`updateReadingProfile`、`updateReadingPlan` 為 `asia-east1` 的 callable functions。身分一律來自驗證過的登入 token，計算依據為 Firestore 的計畫與摘要。

- `bibleProgress/lifeProgress` 與 `baseBible/baseLife` 屬於目前書目。
- `bibleRead/lifeRead` 是這座花園中實際閱讀的累積量；起始進度不計獎勵。
- `archivedBibleRead/archivedLifeRead` 是已封存書目的累積閱讀量，舊資料缺值視為 0。
- 一致性條件：目前已讀位置 = 起始位置 + 累積閱讀量 − 已封存閱讀量。
- 書目變更時，交易封存每個成員對應書目的摘要到 `members/{uid}/readingPeriods`，歸零該書目的起始／目前位置，並遞增書目期別和計畫版本。未變更的項目保留。
- 換回同一本書仍是新的一輪，不覆寫先前摘要。封存包含尚未讀完的書，不代表完成整本。
- 全花園的獎勵累積、連續日期與已取得／放置的 emoji 保留。第一次閱讀後獎勵門檻固定。
- 新閱讀紀錄保存書名、期別、前後位置及對應獎勵 ID；缺書名的舊紀錄不猜測補值。
- 閱讀與計畫請求均使用固定 requestId 和去重收據；相同請求重送不再次寫入。跨裝置舊版本回報衝突，須重新開啟表單。
- 封存進度僅本人可讀，前端每頁按需讀取 12 筆。全體成員的摘要與新書位置在換書時一起更新。

目前換書交易最多支援 60 個成員，供小型封閉共讀使用。尚未引入大量成員的分批換書作業。換書時連同共用摘要與私人摘要原子更新。

## 閱讀更正與提醒

測試版提供「更正最近一次閱讀」：`previewReadingWithdrawal` 先顯示可信任後端計算的進度變化、獎勵與已放置數量，再由 `withdrawReading` 原子撤回。只允許本人撤回最新提交且受影響書目尚未換期的紀錄；換書本身不撤回任何獎勵。

- 同一交易還原進度、累積量、紀錄筆數、最近閱讀日期與連續閱讀日期，刪除該筆對應獎勵及公開擺設。同日還有其他紀錄時保留當天閱讀；其他成員與其他紀錄的獎勵不受影響。
- 原紀錄與當時獎勵快照私密封存在 `members/{uid}/withdrawnReadings`，本人可依規則分頁讀取，網站暫未提供封存更正紀錄清單或一鍵還原。原請求收據標記已撤回，不能重送舊請求再次發獎。
- 確認綁定閱讀、計畫及收藏版本；其他裝置新增閱讀、換書或改變獎勵時要求重新預覽。撤回收據使重試不重複執行；重新記錄後，舊擺設連結也不能操作新獎勵。
- 本人摘要保存最近一次 `lastCorrection`，畫面顯示撤回原因與數量。提醒可在當次頁面關閉，重新登入／載入仍可看到，不發公開通知或郵件。成員共用摘要不包含提醒或獎勵來源。
- 所有擺設都被撤回後，灰階示意會再次出現。`readingStarted` 也維持 true，獎勵門檻不因清空紀錄而重新解鎖。
- 新提交最多產生 200 個獎勵，確保連同已放置項目可在一次交易內撤回。舊紀錄若缺前後位置、來源資料不一致，或獎勵與擺設刪除合計超過 450 筆，先拒絕並要求管理者核對，不做部分撤回。

發布時須包含兩個新 callable、`logs` 的 UID／revision 降冪索引和新版私人摘要；重新執行讀取模型遷移可補上 `lastLogId`、`lastCorrection` 與初次設定狀態。原始成員沒有最新紀錄指標時不猜測歷史順序；之後的新提交可正常更正。

## 初次加入

建立或加入新花園時，初始成員必須有 `onboardingComplete: false`，由配套規則驗證。進入畫布前填寫暱稱及目前選用項目的起始位置；可信任的 `updateReadingProfile` 完成設定，起始位置不發獎。尚未完成設定不能記錄閱讀。

既有成員缺少此旗標視為已完成，不強迫重新設定或清空原進度。每座花園獨立設定；公開預設暱稱不再取 Email 前綴。加入碼可貼上六個不同的既有 emoji，或包含「歡迎加入共讀花園！邀請代碼寄來咯：」的完整邀請文字；忽略空白與 emoji 變體選擇符號，保留順序並拒絕其餘額外字元。

## 資料讀取與隱私

- `memberSummaries/{uid}`：同花園成員可讀，僅包含 UID、名字、三項目前進度、最近閱讀日期。文件 ID 固定排序，不依進度排名。
- `members/{uid}`：完整計算狀態只有本人可取得，禁止列出全體；一般畫面不下載它的完整日期陣列。
- `members/{uid}/private/progress`：本人摘要，含起始位置、累積／封存量、進度版本、紀錄筆數、收藏版本和最新連續天數。閱讀、起始位置及換書交易一起更新兩份摘要。
- `logs`、`rewards`：只有資料的本人能讀取，花園管理者也不能透過網站讀取其他人的心得、詳細紀錄或獎勵來源。具 Firebase 專案管理權限的維護者仍可使用受信任後端工具；這不是端對端加密。
- `placements`：同花園可讀，只有 UID、emoji、座標。使用隨機 ID，不洩漏原獎勵 ID 中的閱讀種類和累積序號；對應表 `placementLinks` 僅後端存取。
- `updateGardenReward` 以登入身分核對獎勵，並用交易更新私人獎勵、共用擺設與收藏版本。放置碰撞只查附近範圍；共同版本欄位讓並行放置重新檢查。`hasPlacedEmoji` 僅保留為歷史欄位，不再控制灰階示意。
- 花園列表只監聽本人索引，不再逐座監聽所有花園。`renameReadingGarden` 原子更新花園名稱及成員索引。

目前常駐監聽為本人花園索引、使用中花園的計畫、共用成員摘要和本人進度摘要；不監聽任何閱讀明細或完整獎勵集合。

閱讀紀錄、過往書卷點開後每頁讀取 12 筆；個人頁收藏每頁 24 筆、只查本人未放置的獎勵。游標含文件 ID，避免同日期漏筆或重複。規則要求查詢帶本人條件及每頁最多 24 筆；這是單次查詢大小，不是每日讀取限額。

灰階示意依整座花園是否有真實擺設判斷：進入畫布或擺設版本變更時，以 `placements` 的 `limit(1)` 查詢確認，與平移／縮放無關。全部收回或撤回後再次顯示；讀取中不猜測為空，錯誤提供重試。示意只在本機呈現，試放功能仍限開發者。

放置預覽支援滑鼠／觸控 Pointer Events 拖曳及方向鍵微調。選取收藏後先在畫布中央預覽；移動既有擺設則優先保留畫面中的原位置。拖曳過程只更新本機座標，不寫入 Firestore；按「確認放置」才呼叫原有 `place` 交易。取消保留原擺設，觸控中斷／失去指標捕捉則還原該次拖曳起點。只有 emoji 把手使用 `touch-action: none`，空白區域保留既有畫布與頁面捲動行為。iPhone Safari 觸控手感仍待實機驗收。

畫布依可見矩形加緩衝區查詢，每頁最多 200 個擺設；較多時顯示載入更多。平移查詢有 250ms 延遲與區域量化，避免每次指標移動都發查詢。只保留最近 8 個區域的短期快取。Firestore 對多範圍索引的掃描仍可能有費用，正式六人測試後需觀察實際用量，不能把傳回筆數當成全部計費讀取量。

私人分頁快取存在目前頁面的記憶體，60 秒內返回可重用；新增閱讀、換書、收藏更新時失效，也提供重新整理。切換花園／帳號會卸載清除，不寫入永久瀏覽器快取。待確認的提交可能包含心得，僅暫存在帳號與花園隔離的 `sessionStorage`，登出時清除；舊版 localStorage 提交草稿在登入狀態初始化時清理。若清除後仍有未知提交結果，伺服器的進度版本會阻擋舊版本重複寫入。

查詢失敗顯示錯誤與重試，不當成空花園；共同計畫、同伴摘要及本人摘要全部就緒後才顯示花園。跨裝置心得編輯不常駐監聽，可按重新整理，或離開再返回時依快取期限更新。

## 測試

需要 Node.js 22 與 Java 21。

```sh
npm run test:integrity
npm run lint
npx tsc --noEmit --incremental false
npm run build
```

整合測試使用 `demo-life-study` 的 Auth、Functions、Firestore 模擬器，不存取正式資料。測試包含身分、本人權限、偽造寫入、去重、交易回滾、跨裝置競爭、換書封存與多花園隔離。

測試使用 `firebase.test.json` 的獨立連接埠 8180／9199／5101，避免清除開發預覽中的資料。測試腳本會清除測試模擬器資料，不能指向正式服務。

## 本機互動預覽

先在一個終端啟動模擬器：

```sh
npx firebase emulators:start --project demo-life-study --only firestore,auth,functions
```

另開終端建立本機帳號並啟動網站：

```sh
FIRESTORE_EMULATOR_HOST=127.0.0.1:8080 FIREBASE_AUTH_EMULATOR_HOST=127.0.0.1:9099 node functions/seed-local.mjs
NEXT_PUBLIC_USE_FIREBASE_EMULATORS=true npm run dev -- --webpack --hostname 127.0.0.1
```

本機帳號為 `owner@example.test`、`reader@example.test`，密碼均為 `GardenTest123!`，僅存在 demo 模擬器。初始化腳本不覆寫既有本機花園或帳號。未匯出模擬器資料時，關閉模擬器會清除本機測試資料。正式 build 不啟用這個模式。

可選書目與目錄整理方式見 [文集目錄說明](cwwl-catalog.md)。文集的 `baseCwwl`、`cwwlProgress`、`cwwlRead`、`archivedCwwlRead` 遵循同樣的一致性條件；舊成員缺少這些欄位時視為 0。

若本機 Turbopack 不可用，可以 `npx next build --webpack` 驗證靜態匯出。

## 既有資料核對

既有 UID、帳號、花園、閱讀紀錄與獎勵保留。後端寫入需要 garden/member 的 `schemaVersion: 2`。管理者以 Application Default Credentials 明確指定專案和花園，先執行唯讀核對：

```sh
node functions/audit-garden.mjs PROJECT_ID GARDEN_ID
```

核對工具分頁讀取資料，比對摘要、歷史閱讀量、封存及應有獎勵；無法還原缺失書名或證明舊有閱讀內容的真實性。不一致必須人工處理，不會自動刪除、猜測修復或補發。

## 發布順序

確認 Functions 所需的 Firebase 計費方案、區域和部署權限。先備份資料、安排短暫停止寫入，並檢視核對結果；發布新規則封住舊客戶端直接寫入後，才套用已確認的 metadata 遷移：

```sh
node functions/audit-garden.mjs PROJECT_ID GARDEN_ID --apply-reviewed
```

套用時會在交易內重新核對全部資料，僅加入版本、筆數及最近日期等 metadata，不變動舊紀錄、獎勵與閱讀量。此完整交易僅適合小型測試資料，並非每次閱讀時執行。

在維護時段內，另外核對並建立讀取用資料。此工具預設唯讀，先看結果再明確套用：

```sh
node functions/migrate-read-models.mjs PROJECT_ID GARDEN_ID
node functions/migrate-read-models.mjs PROJECT_ID GARDEN_ID --apply-reviewed
```

它分頁掃描成員與獎勵，逐筆交易建立安全摘要、索引與既有擺設的隨機對應 ID；可重跑，不刪除閱讀、帳號或獎勵。先跑前述完整性核對；若摘要尚未升級、資料不一致或中途失敗，先修正並重跑，不開放新版前端。此遷移不是即時雙版本服務，執行期間應停止使用者寫入。

部署 `firestore.indexes.json` 並等索引建置完成，再部署配套 Functions、規則與 Hosting，驗收管理者與普通成員。新版前端、規則及 Functions 必須配套發布；不要單獨部署前端或回退成允許直接發獎的舊規則。

`.github/workflows/pages.yml` 是既有 GitHub Pages 流程；Firebase Hosting 需另外發布。模擬器測試通過不等於已完成正式站與手機驗收。
